## 1. 一句话概述

志愿者端有**两条并存的演示主线**，现场按网络情况二选一：

| 主线 | 触发 | 现场表现 | 依赖 |
|---|---|---|---|
| **A · 视频疏导**（原方案） | 点「打开视频窗口」 | 真拉起 Jitsi 房间，队友在另一台设备出镜 | **需要外网** |
| **B · 真拨电话**（路演主线） | 点「拨打求助者」 | 志愿者用**自己手机**真拨号，大屏跟进"呼叫中 → 通话中 + 计时" | 不需要外网 |

两条线并存是**加法**：视频那套一行没删，随时能退回原方案。默认走哪条由现场决定，
代码里靠 `callState`（`none` / `calling` / `connected`）分叉，互不干扰。

## 2. 七个阶段的渲染分支

契约 §4.2 要求每个模块处理全部 7 个阶段，志愿者端一个都不能空：

| 阶段 | 角标 | 屏内容 |
|---|---|---|
| `IDLE` / `SOS_TRIGGERED` / `INSTITUTION_ALERT` | 在线待命（绿） | 工作台：本人姓名、距求助点距离、技能标签、资质说明 |
| `AUTO_ESCALATE`（未接单） | ● 新派单（红）／↻ 已转派 | 派单卡片 + 地图 + **5 秒接单倒计时条** + 接单按钮；转派后卡片变黄并写明"上一位未在 5 秒内响应" |
| `AUTO_ESCALATE`（已接单） | 已接单（蓝） | 地图 + 「拨打求助者」/「改用视频疏导」 |
| `VIDEO_SESSION`（电话线） | ● 呼叫中 / ● 通话中 | 通话卡（三态）+ 地图 + 「我已到达现场」 |
| `VIDEO_SESSION`（视频线） | ● 待接通 / ● 视频中 | 通话画面（`feature.video.js` 单一来源）+ 地图 + 打开视频 + 到场 |
| `ON_SITE` | 已到场 / ● 通话中 | 到场打卡卡 + 地图；**电话还通着就继续显示通话卡** |
| `CLOSED` | 已闭环 | 感谢 + 48 小时内推送同伴心理支持 |

## 3. 关键实现决定（都有原因，改之前先读）

### 3.1 接单倒计时与超时转派（UI-31）

- `AUTO_ESCALATE` 进入时起 5 秒倒计时（`CONFIG.VOLUNTEER_ACK_SEC`），条与数字都走 1 秒心跳。
- 超时 → `activeIdx++` 转派下一位，**地图上留一条灰色虚线**表示"这段没走完"，
  再重新起一轮倒计时；没有下一位就写时间线"全部志愿者均未响应，等待人工介入"，流程不中断。
- **转派后必须仍然能接单**——否则下一位接不了，流程就断在这里。

### 3.2 距离递减用「相对时间」，不是全局 `elapsedMs`

原实现用 `App.state.elapsedMs` 算进度：它只在**正常点按钮求助**时才开表，
用 `App.jump()` 跳阶段时恒为 0 —— 结果是进了 `VIDEO_SESSION` 距离恒为 0、圆点不动。
现在以"进入本阶段的 `Date.now()`"为零点算 `travelPct()`，任何进入方式都正常走。

### 3.3 地图圆点真的在动，不是只改数字

每 200ms 的 `timer:tick` 里调 `patchMap()`，**只改** `.dot-me` 的 `cx/cy`、路线的 `x2/y2`
和距离文本，不整块重绘 —— 否则每 200ms 重绘会把动画和按钮状态冲掉。
（`tools/volunteer-smoke.js` §5 专门断言"距离在减 + 圆点在动"两件事。）

### 3.4 到场只 `emit`，阶段由 core 推进（契约 §1 / §5）

点「我已到达现场」时本模块**不调用** `App.next()`，只 `emit('volunteer:onSite')`，
由 `core.state.js` 里新增的订阅统一走 `VIDEO_SESSION → ON_SITE`，并带 stage 校验防重复点击。
这与 A 端 `sos:tap`、B 端 `institution:ack` / `demo:closed` 的做法一致（见契约 §9 变更记录）。

### 3.5 为什么不使用 `App.delegate`

`core.state.js` 的 `App.delegate` 用 `sc.__delegated` 做一次性守卫，
**一个角色只有第一次调用是活的**。志愿者端要 6 个按钮，所以自己绑一个原生委托，
按 `data-act` 分派；容器 `#volunteer-screen` 永不重建，只需绑一次。
缺陷细节见 `tools/dev-board.md` §五，等框架负责人评估改成 `__delegates` 数组。

⚠️ 教训（写进 smoke 测试）：只断言"元素存在"会漏掉"表停了但元素还在"这类 bug，
所以计时类断言必须比较**秒数在变**，不能只比较元素存在。

### 3.6 视频降级画纯 CSS，不再依赖图片

原实现引用 `assets/video-fallback.png`，但该文件不在仓库里，load 失败只剩一个 emoji。
现在 `App.callScreenHTML()` 用纯 CSS 画"对方出镜 + 本机小窗 + 波形 + 房间名 + 通话控制"，
不引用任何图片文件，离线可用。

- 弹窗被拦时**算已接通**（`videoRoom` 写 `fallback-` 前缀），流程不会卡在 `VIDEO_SESSION`；
- `fallback-` 前缀有两个用处：宫格④ 显示"占位画面"并**隐藏房间名**，队友一眼看出这次没真拉起来；
- `video:open` 事件 payload 增加 `fallback` 字段，原有 `room` / `url` / `ok` 三个字段不变。

### 3.7 通话三态与"不许冻表"

真实通话状态网页拿不到（电话一接通系统就把通话交给电话 App，浏览器被切后台；
麦克风检测又要 secure context，而我们是 `file://` 打开）。所以"已接通"由志愿者点一下确认——
真实产品里志愿者本来也要点这一下。两个细节：

- 通话期间**距离冻结**（人在原地打电话，不该继续往前走）；
- `VIDEO_SESSION → ON_SITE` 时**不清通话计时**（电话还通着），挂断动作里才停表。
  早期版本在 `arrive` 里 `clearTick()`，大屏计时冻在 `00:00`，看着像坏了。

